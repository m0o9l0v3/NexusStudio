## 手順

1. **CLI（`ASPNETCORE_ENVIRONMENT=Production`、`nexus_studio_app`）で用意**：`admin add`、`reference import`（開催回・開催日 2027-09-20・カテゴリ・Spot `mb_1f_cl_001`）、`map import`（v1）
2. **開始状態の公開**（Web API を Development で起動、同じ `nexus_studio_app`）：地図 v1、開催回・カテゴリ・Spot、会場を `mb_1f_cl_001` にしたイベント1件を公開。下書きだけのイベントを1件作る。その後 Spot を新規選択停止にして公開する（PR #26 のレビュー指摘2）
3. 既存の alias `old_cl_001 → mb_1f_cl_001` を `nexus_studio_app` で予約表に追記
4. **拒否の確認**（Production の `spot rename`）：何も変わらないこと（Release・Spot・予約表・イベントの版・bundle の件数と配信ポインタ）を各回確かめる
5. 地図 v4（目的地の ID を `mb_1f_cl_002` に替えたもの）を最後に取り込み、`--apply` なし → `--apply` で改名
6. DB を superuser で読み、bundle は `nexus_public` で読んで確かめる

### 途中の失敗（試験側の誤り）

- 1回目：試験スクリプトが CSRF ヘッダー名を誤った（`X-CSRF-TOKEN`。正しくは `X-XSRF-TOKEN`）ためログインが 400。スクリプトを直し、環境を作り直した
- 2・3回目：改名は成功したが、Release の内容と公開状態の照合で、期待値の並び順（`mb_1f_cl_002` を先に書いた）が DB の並び順と違って不合格。実際の値は期待どおりだった。照合を順不同に直し、環境を作り直して最初から通した（上の結果は4回目）

いずれも Studio のコードは変えていない。
