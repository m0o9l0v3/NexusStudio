## 1. 公開処理の作り（コードで確認）

- 「公開処理中」の操作ログを**トランザクションの前に**確定させ、Release・Publication・ログの完了を1つのトランザクションで書く（`PublishingService.cs`）。
- 公開は `pg_advisory_xact_lock(7201)` で1つずつ。公開直前に候補を組み立て直し、確認した検証結果の指紋（Fingerprint）と照合する。
- 処理中のまま2分を過ぎた操作は、照会で「未反映の失敗」とする（`AbandonedAfter`）。

## 5. 所見・判断事項

- **C-D1（判断事項）** R03 に「基準（直前の Release → 新しい Release）」の行が無い。結果の API は対象ごとの直前の版（`previousRevisionId`）は返すが、直前の Release の通し番号は返さない。推奨：Release 詳細へのリンク（実装済み）で差分を確認できるため、R03 からは行を省き Figma要反映とする。もう一案は API に直前の Release を加えて表示する。
- **O1（軽微）** 公開の途中で止まった操作は、Logs の対象名（`targetLabel`）が空になる（対象名をトランザクションの中で書くため、ロールバックで消える）。対象ID は残る。推奨：対象名を「処理中」記録と同時に書く小さな修正。
- **検証器の失敗（#7）** は実 PG で再現していない（上記）。
