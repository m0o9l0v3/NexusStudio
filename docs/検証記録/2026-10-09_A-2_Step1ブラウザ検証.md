## 不具合・差分

### B1 別の管理者で再ログインすると、前の管理者の未保存入力が残る（❌）

- 期待：UI補完記録 2026-09-23 L05「別の管理者で再ログインした場合は、前の管理者の画面状態を破棄してOverviewへ移る」、24 §2 1-c。
- 原因（コード確認）：`apps/studio-web/src/auth/SessionExpiredDialog.tsx` の `navigate('/overview')` が、未保存の変更があると LeaveGuard に止められる。また `queryClient.clear()` の後に `setQueryData` しても、表示中の Sidebar はセッション情報の更新を受け取らない（再読み込みで直る）。
- 影響：別の管理者が前の管理者の未保存入力をそのまま保存できる。操作ログの実行者が実際の入力者と食い違う。
- **修正（2026-10-09）**：別の管理者のときは `skipUnsavedGuard` を付けて Overview へ移動し、未保存の入力を確認なしで破棄する。`queryClient.clear()` をやめ、セッションを更新したうえでセッション以外のキャッシュだけを捨てる（表示中の Sidebar が新しいセッションを受け取る）。
- **再確認**：A で未保存入力 → 別タブでログアウト → 保存で L05 → B で再ログイン。S03 は出ずに `/overview` へ移り、Sidebar は「検証管理者B」、`/events/new` は空、`studio.event_heads` は0件（画像15）。同じ管理者の場合の処理（else 側）は変更していない。
- 自動テスト：Web には単体テストの仕組みがないため、ブラウザでの再確認を証拠とする。

### B2 パスワード再発行・無効化の反映が最大1分遅れる（所見）

- `AuthServiceCollectionExtensions.cs:68` でセキュリティスタンプの確認間隔を1分にしている。自動テスト（`StudioApiFactory.cs:48`）は間隔を0にしているため、この遅れを捉えていない。
- CLI は「既存のログインセッションは失効します」とだけ表示し、遅れには触れていない。#22 の無効化がすぐ反映されたのは、そのセッションが前回の確認から1分以上経っていたためで、無効化も同じく最大1分遅れうる。
- 決定事項に「即時」の定めはない。
- **対応（2026-10-09 利用者判断：推奨どおり）**：確認間隔を0にし、毎回再検証する。テスト側だけの上書き（`StudioApiFactory`）は外し、本番と同じ設定で `ResettingThePassword_EndsExistingSessionsAndAcceptsOnlyTheNewPassword` が守るようにした（1分に戻すとこのテストが失敗することを確認）。隔離PGで、再発行・無効化とも直後の要求で既存セッションが 401 になることを確認した。

### D1 ログイン失敗後にパスワード欄が空になる

- Figma L02／L04 はパスワード欄に入力が残った状態。実装は失敗時に消す（`LoginPage.tsx` `setPassword('')`）。
- 決定事項に定めはない。
- **対応（2026-10-09 利用者判断：推奨どおり）**：実装のまま空にする。UI補完記録の該当行（2026-09-23 L02）を L04 にも広げ、「Figma要反映」にした。

### D2 共通 Dialog を閉じた後、フォーカスが元の場所に戻らない（a11y）

- 共通の `apps/studio-web/src/ui/Dialog.tsx` が Radix の Trigger を使っていないため、閉じた後に戻す先がない。L06・E32 で確認。ほかの共通 Dialog（S03・L05 など）も同じ作りのため、同じ挙動の可能性が高い。
- ログイン失敗後もフォーカスが `body` に落ちる（送信ボタンを無効化したため）。エラーは `role="alert"` で読み上げられる。
- CLAUDE.md の「エージェントが補完してよいもの」（フォーカス管理）に当たる。A-6 で修正し、UI補完記録へ追記する。

### D3 準備中画面の文言が古い

- 「この画面はStep 3以降で実装します」。現在は Step 4 まで実装済みで、Overview は 24 の D、Map Data は E／F の範囲。文言の更新は軽微な補完として A-6 で扱う。

## 環境の記録

- アプリ内プレビューから起動したプロセスは `.env` を読めなかった（`Operation not permitted`）。そのため API がパスワードのない接続文字列で起動し、ログインが 500 になった（#7 の画像）。API は Bash から起動し、`.claude/launch.json` は Web だけにした。
- 接続文字列が「設定されている」ことしか起動時に検査しないため、パスワードが空でも起動できる。接続の可否は最初の要求まで分からない（既定値を持たせない方針は守られている）。
