## 1. 正規化バイト比較の自動テスト

[15 v02](../決定事項/15_NexusStudio_実装開始判断・初期実装計画_2026-09-22_v02.md) は保存payloadと再取得payloadの「JSON正規化バイト比較」を自動テストに求めている。既存の `SavedDraft_RoundTripsWithoutLosingOrChangingAnything` は `JsonNode.DeepEquals` による比較だった（10-18 照合 §5）。

追加したテスト（`EventEndpointsTests.cs`）：

| テスト | 内容 |
|---|---|
| `CanonicalBytes_KeepsArrayOrderAndCaseButIgnoresKeyOrder` | 正規化（オブジェクトのキーを序数順に並べ、空白なしの UTF-8 に書き出す。配列順・文字列・null はそのまま）が甘くないことの確認。キー順だけの違いは同じバイト列になり、配列順・大文字小文字・`null` の有無の違いは別のバイト列になる |
| `SavedDraft_CanonicalBytesMatchTheSentPayload` | 複数枠・複数会場・終日・随時参加・未選択・大文字小文字だけ違う ID を含む下書きを作成し、送信payload・`GET /api/events/{id}` の `draft`・保存した Revision の JSON の正規化バイト列が一致する。続けて枠順と会場順を入れ替えて更新し、入れ替え後のバイト列（元とは違う）で同じく一致する |

実行結果（SQLite メモリDB、`dotnet test --filter EventEndpointsTests`）：19件合格。CI の結果は PR を参照。

SQLite の合格を PostgreSQL の合格として扱わないため（README）、§2 の6件のイベントについて実PGでも同じ比較をした。ブラウザで `GET /api/events/{id}` の `draft` を同じ規則で正規化して SHA-256 を取り、`studio.event_revisions.payload`（jsonb。キー順が入れ替わる）を Python の `json.dumps(sort_keys=True, separators=(',', ':'), ensure_ascii=False)` で正規化した SHA-256 と比べた。
