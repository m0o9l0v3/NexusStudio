## 1. 承認された範囲

利用者から前記録で提示した確認単位に対して「承認します」との回答を受けた。次を承認済みとして扱う。

- Nexus Studio全体のUI方針：左Sidebar、中央Workspace、必要時の右Inspector、落ち着いた配色、Noto Sans JP、表・フォーム・地図中心の情報配置、保存・公開・検証・結果を分離する状態表示。
- Eventsの主要編集フロー：一覧、枠の複製、複数会場、終日と参加方式、下書き保存、一覧復帰、再表示。
- Eventsの公開フロー：左に差分、右に検証・関連影響、イベント1件全体の公開、公開処理中、公開成功、結果確認中、未反映の失敗。
- 無関係なMap Data下書きの問題は「公開対象外」と示し、現在公開中の地図・Spotを参照するイベント訂正を止めない。
- Studioの公開成功と、全iOS端末への反映完了を同じ状態にしない。

承認は上記のFigma表現・情報設計の範囲に限定する。製品コード、API、DB、実公開、全Studio画面、正式データ、実装技術の承認には拡張しない。

## 2. Overview初期案

- 状態：検討中。今回新たに作成した画面であり、承認済みではない。
- Figma Node：`27:2 O01 Overview — 通常`
- Prototype開始点：「Overview」
- 画面サイズ：1440×1024

### 目的

管理者が、現在何が公開されているか、次にどの下書きや問題を確認すべきかを短時間で判断する。来場者数、人気ランキング、リアルタイム混雑を中心にはしない。

### 情報構成

1. **現在の公開版**：Release ID、公開日時、対象、基準Release、公開状態。
2. **開催情報**：公開中の開催回、日付ごとの一般公開時間、通常／中止。
3. **Data Health**：現在の公開版、全下書き診断、未検証下書きを別行で表示。
4. **未公開変更**：Events、Map Data、Spots、Open Campusごとの下書き状態と次の操作。
5. **最近の操作**：公開、下書き保存、検証を時系列で表示し、Logs詳細へつなぐ想定。

### 判断を誤らせない表示

- 「全下書き診断の公開阻止」と「現在の公開版の状態」を別に表示する。
- 取得失敗を0件・問題なしへ置き換えない。今回の画面は正常取得時の代表状態。
- 「今日」を固定文字や直近日で代用せず、実日付と公開済み開催日から判定する。
- 未公開変更を、そのまま次回の公開対象であるかのように表示しない。
- すべてのイベント名、日時、件数、Release／Revision IDは設計用サンプル。

## 3. Figma確認結果

- `27:2`をスクリーンショットで確認。
- 2列の開催情報／Data Healthで、初回スクリーンショットに状態ラベルの右端はみ出しを発見し、行内のラベル・値幅を調整した。
- 調整後、1440×1024で主要文言、日時、状態ラベルが表示され、文字切れ・重なりは見つからなかった。
- 文字はNoto Sans JP、既存のVariablesと配色を継続。
- 未公開変更のEvents行から`11:2 Events一覧`へ遷移する。

## 4. Overviewで次に用意する状態

通常画面が承認された後、同じ配置を保ったまま次を状態Variantsとして追加する。

- 読み込み中。
- 正式な公開データ0件。
- 取得失敗。
- 以前取得した情報を表示している状態。取得時刻と未更新を明示。
- 複数開催回が公開されている場合の対象選択。
- 開催日の中止がある場合。

Overviewの承認だけで、Spots、Open Campus、Map Data、Validation、Releases、Logs、Loginの個別画面を承認済みにしない。
