# Nexus Studio v1.0 Validation・Releases詳細案

- 作成日：2026-09-13。状態：決定案。確定した公開方針を共通機能へ具体化する。
- 確定事項：[公開方針](06_NexusStudio_v1.0_公開方針・機能境界_2026-09-12_v01.md)。イベント1件・地図全体の公開、選択外の下書きの保持、公開後の整合性確認、部分反映を防ぐこと、履歴・復旧。
- 開催回・カテゴリの公開単位や、参照時間・中止の連動は[開催情報案](08_NexusStudio_v1.0_開催情報・カテゴリ管理詳細案_2026-09-13_v01.md)の追加提案。利用者の明示承認済み事項と区別する。

## 1. 公開単位の整理案

| 対象 | 通常の公開単位 | 選択外の内容 |
|---|---|---|
| イベント | 共通情報と全開催枠・会場を含む1件 | 他イベントと地図の下書きを保持 |
| 地図 | 対象MapDataset全体。Spot属性・建物・道路・入口・必要な経路等 | イベント下書きを保持 |
| 開催情報 | 1開催回と開催日一覧 | 別開催回を保持。影響する終日枠等は確認対象 |
| カテゴリ | カテゴリ一覧 | イベントの分類変更の下書きを保持 |

「Release」は公開操作の履歴と、その結果として利用できるデータの組み合わせを表す案。単一の巨大ファイルを意味しない。イベントを1件公開しても、その版がどの公開済み地図・開催情報・カテゴリと整合しているかを追跡できるようにする。

## 2. 検証対象の作り方

公開する保存版と、選択していない公開済みデータから、公開後の候補を作る。選択外の下書きを検証候補へ混ぜない。候補全体の契約を検証しつつ、警告の重複通知は変更に応じて抑える。

- 管理者向けの全下書き診断と、実際の公開候補の検証を分ける。
- 全下書き診断にエラーがあっても、無関係な公開候補の公開は可能。
- 選択した変更に依存するSpot・開催日・カテゴリ・経路などは公開候補内で検証する。
- 未検証・処理中・検証失敗・合格・警告あり・エラーありを区別する。検証器の失敗を合格と表示しない。
- 公開条件に必要な実測・正式資料が不足している場合は、コード上の検査だけで合格へ変えない。

## 3. Validationの機能一覧

| ID | 機能 | 操作・結果 |
|---|---|---|
| VA-01 | 全体診断一覧 | 領域・状態・件数・最終検証版・時刻を表示 |
| VA-02 | 検証実行 | 下書き全体診断または指定の公開候補を明示して実行 |
| VA-03 | 対象別表示 | Events・Spots・Buildings・Navigation等へ絞る |
| VA-04 | 重要度別表示 | 公開阻止・要確認・情報を区別 |
| VA-05 | 問題詳細 | 対象、理由、問題値、期待する条件、修正方法を表示 |
| VA-06 | 修正先へ移動 | 編集欄・開催枠・会場行・地図地物へ移動 |
| VA-07 | 関連対象の確認 | 公開中の参照と下書きの参照を分けて表示 |
| VA-08 | 再検証 | 修正後の保存版で再実行。古い結果を明示 |
| VA-09 | 根拠不足の表示 | 現地確認・正式情報・データ整備等の必要作業を示す |
| VA-10 | 検証処理の失敗表示 | 内容不備とサービス処理失敗を区別し再試行可能にする |

必要な検証カテゴリは、必須入力、日時、ID、参照、Geometry、正式情報の来歴、経路接続、配信互換性、対象版の競合。具体的な閾値・起点終点集合・対応Schemaはデータ調査後に固定する。

## 4. Releasesの機能一覧

| ID | 機能 | 操作・結果 |
|---|---|---|
| RL-01 | 公開候補の選択 | 保存済みイベント等を選び、対象単位と件数を確認 |
| RL-02 | 公開差分 | 追加・変更・中止・取り下げ・参照に伴う変化を表示 |
| RL-03 | 関連変更の確認 | 未公開会場など必要な対応を示す。自動で下書きを追加しない |
| RL-04 | 公開前検証 | 実際の候補と版に対して検証し、結果を提示 |
| RL-05 | 警告の確認 | 理由と影響を見て続行できる。エラーを警告へ手動格下げしない |
| RL-06 | 公開実行 | 確認した候補を一度だけ反映し、整合した公開版を作る |
| RL-07 | 結果確認 | 成功・未反映の失敗・確認中を区別して公開版と日時を表示 |
| RL-08 | 履歴一覧 | 版・操作・対象・実行者・日時・結果を確認 |
| RL-09 | 履歴詳細 | 公開した内容と参照データの組み合わせ・差分を確認 |
| RL-10 | 過去版を復旧候補にする | 戻す単位と現行版との差分を示す |
| RL-11 | 復旧検証・実行 | 現行の関連データと検証して、新しい公開として反映 |
| RL-12 | 既存下書きの保護 | 復旧・取り下げで未公開編集を消さず、退避・確認の導線を提供 |
| RL-13 | 結果不明時の照会 | 通信が切れても実際の操作状態を取得。無条件再公開しない |
| RL-14 | 競合確認 | 確認後の編集・関連公開の変化を検知して必要な再確認を行う |

## 5. 公開確認画面案

上部に対象と操作、中央に差分、右側に検証・関連影響を表示する。最終ボタンは「イベント2件を公開」「地図を公開」「イベントを取り下げ」等、実際の操作を示す。公開メッセージは任意とする案。

一括公開対象の1件がエラーなら、その候補のままでは全件未反映にする。管理者が対象から外し、残りの候補で検証・再確認して公開する。エラー対象をシステムが黙って除外して一部成功とする方式は採用しない。

保存不足のときは「保存して確認」へ導き、未保存の画面と公開対象が違うまま進ませない。Previewは確認を助ける表示であり、表示しただけで検証済みと扱わない。必須のPreview閲覧回数や別人の承認は追加しない。

## 6. 操作によって異なる検証

| 操作 | 対象 | 不完全な下書きの扱い |
|---|---|---|
| 通常のイベント公開 | 保存済みのイベント全体 | そのイベント内の不足は阻止 |
| イベント取り下げ | 現在の公開を無効にする変更 | 内容を公開しないため、下書きの入力不足は阻止理由にしない |
| 地図公開 | Dataset全体と公開済み参照元 | 無関係なイベント下書きを混ぜない |
| 開催時間の参照更新 | 公開中イベント内容を基準に時間を再解決する追加案 | イベントの編集中の内容を混ぜず保持 |
| 過去版から復旧 | 指定単位の過去版全体＋現行の関連公開データ | 下書きを消さず保護。過去版の参照欠落は阻止 |

イベント取り下げも権限・対象版・公開整合性を確認する。緊急性によって検証を無効にする操作は設けない。

## 7. 復旧の初期案

- イベント1件、地図全体、開催回、カテゴリ一覧の各単位で過去版を選ぶ。
- 過去版を選んだだけでは本番を変更しない。現行との差分と関連影響を確認する。
- イベント復旧では全枠・全会場を含む過去の内容を候補にする。ただし終日の実際の時刻は現行の開催情報と整合させ、当時と違う値を確認画面で明示する案。
- 地図復旧で現在のイベントが使うSpotが失われる場合、そのままでは復旧できない。必要な関連訂正を別途準備する。
- 開催回の復旧は現在のイベント日付や終日時刻、中止への影響を確認する。カテゴリ復旧は既存参照を失わせない。
- 現在の未公開下書きがある場合は退避版を作成し、後で内容を参照して下書きへ復元できる操作を必要とする。復元でも最新の下書きを無確認で上書きしない。
- 退避・復旧履歴の保持期間、画像や地図の旧版保持容量は技術設計で決める。参照中の版や素材を削除しない。

復旧は誤った公開から戻るための製品機能。バックアップからの災害復旧とは区別し、片方の存在で他方の完成を宣言しない。

## 8. 配信整合性と完成条件

公開操作の成功は、サーバー側で確定し配信可能な整合した版が用意されたこととする案。全端末への即時反映完了ではない。端末は整合するデータ一式を検証してから切り替え、途中取得や失敗で新旧が混在した状態を使わない契約を必要とする。

既存API・iOS・オフラインパッケージの仕様を調査し、版の対応・旧クライアントとの互換性・画像等の保持・キャッシュ・更新失敗を確認する。Studioだけの画面テストで、利用者への正しい反映まで完成扱いにしない。

## 9. 受け入れ条件案

| ID | 状況 | 必要な結果 |
|---|---|---|
| RA-01 | 全下書き診断には無関係なエラーがある | 有効な公開候補は公開可能 |
| RA-02 | 未公開Spotが必要 | 理由と修正先を示し、自動公開しない |
| RA-03 | 一括対象の1件が不正 | 候補全体を未反映に保つ |
| RA-04 | 確認後に関連データ変更 | 古い確認結果を使わず再検証・再確認 |
| RA-05 | 連打・再試行 | 重複Releaseを作らない |
| RA-06 | 応答前に通信切断 | 実状態を照会し、成功・失敗を推測しない |
| RA-07 | 検証サービスが失敗 | 検証エラーとして扱い公開を止める |
| RA-08 | 地図の旧版に会場が存在しない | 整合しない復旧を阻止 |
| RA-09 | 復旧時に未公開下書きがある | 退避し、参照・復元可能にする |
| RA-10 | 旧時刻の終日イベントを復旧 | 現行の開催時間との違いを示して確認 |
| RA-11 | 端末が一部データ取得に失敗 | 直前の整合した保存版を維持 |
| RA-12 | 公開履歴を確認 | 実行者・対象版・内容・結果・日時を特定できる |

未決事項は、正式なValidation規則・データ契約・保存期間・技術実装方式・代表データでの処理時間。既存実装がこれらを満たすかは未調査。
