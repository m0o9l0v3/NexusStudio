# Nexus Studio v1.0 Map Editor詳細案

- 作成日：2026-09-13。状態：決定案。操作・データ境界・初期対象外の追加判断は提案。
- 確定境界：PCブラウザ専用。直感的な地図編集。建物・道路の新規作成は含めない。地図はひとまとまりで公開。
- 関連：[Spots詳細案](09_NexusStudio_v1.0_Spots管理詳細案_2026-09-13_v01.md)、[公開方針](06_NexusStudio_v1.0_公開方針・機能境界_2026-09-12_v01.md)。
- 資料境界：構内GeoJSON・実測資料・ID台帳を基礎にする。古いPDFは参考。実データの最新の完全性や具体的な高さ・経路は未検証。

## 1. v1.0の操作範囲案

既存建物の2D形状・属性を編集して3Dへ反映し、Spotの配置・属性編集を行う。3D空間での精密な立体モデリングは行わない。2Dで形状を調整し、3Dで高さと周辺関係を確認する。

| データ | 表示・確認 | 初期の編集案 | 公開時の扱い |
|---|---|---|---|
| Buildings | 2D輪郭・3D押し出し・属性 | 既存Polygonの頂点、名称・高さ・階数等 | 地図版に含む |
| Spots | ピン・階・属性・会場参照 | 新規下書き・属性・位置変更 | 地図版に含む |
| Roads | 既存形状・属性 | 初期は読み取り専用を提案。既存道路の編集は未決定 | 既存データを保持して地図版に含む |
| Entrances | 位置・親建物・出典・関連経路 | 初期は読み取り専用を提案 | 必要な正式データを保持 |
| Navigation | Node・Edge・接続・問題箇所 | 初期は読み取り専用を提案 | 検証済みデータを保持 |
| 屋内図・階層 | 既存の利用可能な情報 | 専用Indoor Editorは後続案 | iOSの屋内案内に必要なデータは除外しない |
| 参考背景 | 表示、表示切替 | 編集しない | Nexus正規データへ混入させない |

既存道路・入口・経路の読み取り専用化は、利用者が新規作成を対象外とした判断とは別の提案。iOS v1.0の屋外・屋内・階層間・屋内外経路案内、オフライン利用の範囲を縮小しない。

## 2. 地図公開の境界案

1つのMapDatasetの整合する公開版として、Spot属性・建物・道路・入口・必要な階層／経路データと、配信に必要な対応情報をまとめる。論理的な公開単位の案であり、単一ファイルや単一DBテーブルを要求しない。

公開時には編集対象だけを再出力して残りを落とさず、読み取り専用・未対応の既存情報を保持する。外部背景・編集カメラ・レイヤーの一時表示設定・UIの選択状態は本番データへ混ぜない。複数キャンパス・複数Dataset切替は初期に必須とせず、現行の対象Datasetを明示する。

## 3. 建物の項目案

| 項目 | ルール |
|---|---|
| 建物ID | 正式IDを維持。名称や位置変更で変えない |
| Polygon | 正のGeoJSONを基礎とする。既存の穴・複数形状等を表示できない場合は編集を制限して保持する |
| 名称・用途 | 正式情報に基づいて編集 |
| 高さ | 単位をmで明示。正式値・未確認・表示用仮値を区別 |
| 階数 | 整数の属性。階のID一覧や階高とは区別 |
| baseHeight | 必要性をデータ調査後に判断。初期に編集欄を追加しない案 |
| 出典 | 資料名・測定記録・確認時点等を保持 |
| 表示設定 | 表示対象とするかを編集。建物の公開取り下げとは分ける |

階数×仮の階高から正式な高さを自動生成しない。高さ変更で階IDや経路の高さを自動修正しない。高さ不明の建物は、初期案として2D輪郭と「高さ未確認」を表示する。3D表示のための仮の高さが必要なら、Preview専用の区別された値として設計し、正式データへ保存しない。

## 5. マウス・キーボードの操作方針案

通常は選択とカメラ移動。形状編集とSpot移動は明示的に開始する。Escは現在の編集をキャンセルし、削除キーは編集中の選択頂点など対象が明確なときだけ働く。テキスト入力中に地物削除へ転用しない。

編集の完了・取消はボタンからも実行できる。ホバーだけに重要情報を置かない。重なったSpotは候補を選べるようにし、背面の別地物を暗黙に動かさない。ショートカットの最終割当は使用ライブラリを決めてから確定する。

Undo／Redoは現在の編集セッションの操作を対象とし、本番公開を戻す機能ではない。保存後の履歴保持とタブ再読み込み後の復元範囲は実装契約で明示する。公開後の復旧はReleasesで行う。

## 6. 形状・位置・経路の検証

| ID | 条件 | 判定案 |
|---|---|---|
| MV-01 | Polygonの最低頂点数・閉合・自己交差等が不正 | 編集確定または公開を阻止。具体的対応形状はSchemaで定義 |
| MV-02 | 座標系不正・非数値・範囲外 | 保存／公開阻止 |
| MV-03 | 高さの単位・値が不正、階数不正 | 公開阻止。閾値は推測で固定しない |
| MV-04 | 正式値と推定値の混在、必要な出典未確認 | 対象属性の正式公開を阻止 |
| MV-05 | 存在しない建物・階・Spot等への参照 | 公開阻止 |
| MV-06 | 入口・到着点・Graphの整合性が破損 | 公開阻止 |
| MV-07 | 建物輪郭変更が入口・Spot・経路に影響 | 依存する位置・接続を検証。未検証なら合格にしない |
| MV-08 | 読み取り専用データが保存時に消える・変わる | 保存／公開阻止 |
| MV-09 | 地図取り下げが公開中イベントの会場を壊す | 公開阻止 |

道路の線や建物の角から入口・歩行可能性・段差なしを推測しない。経路到達可能性の検証には起点・目的地・対象条件が必要であり、「検証処理を呼べた」だけで合格にしない。

## 7. データ導入・外部依存

- 初期データは正式資料から変換・照合し、原本を保持する。実装用の導入手順を整える。
- 汎用GeoJSONインポート／エクスポートUIは初期対象外案。既存の形式・ID・参照・差分を壊さず導入できる手順の用意は必要。
- 経路・入口などStudioで編集しない情報の訂正は、検証済みデータを下書きDatasetへ導入し、通常と同じ公開検証を通す。実DBへの直接反映を通常運用として要求しない。
- 外部背景・3Dサービスをv1.0の必須依存にしない。採用時には提供地域・費用・利用条件を調査するが、本書では採用・料金を断定しない。
- MapLibre等は元資料の候補のまま。ライブラリ選定・対応Geometry・保存契約・性能予算は実装前の調査事項。

## 8. 受け入れ条件案

| ID | 状況 | 必要な結果 |
|---|---|---|
| MA-01 | 2Dから3Dへ切替 | 同一データの選択・変更を維持 |
| MA-02 | 正式な高さを編集 | Previewへ反映し、保存・公開状態を区別 |
| MA-03 | 高さ不明の建物 | 階数等から正式高さを捏造しない |
| MA-04 | 既存頂点を移動・取消 | 開始前へ戻り、他の地物に影響しない |
| MA-05 | 自己交差する形状を作る | 問題箇所を示し公開を防ぐ |
| MA-06 | 穴や未対応の複数形状を含む | 無断で単純化・消去しない |
| MA-07 | 建物輪郭が入口との関係を変える | 依存検証を要求する |
| MA-08 | Spot名だけを変更して地図公開 | 他の地図変更も確認対象であると分かる |
| MA-09 | 背景を取得できない | 正規データと背景失敗を区別 |
| MA-10 | 既存経路レイヤーを編集せず保存 | 内容を失わず、必須の案内データを保持 |
| MA-11 | Undoを実行 | 本番公開が勝手に巻き戻らない |
| MA-12 | 新規建物・道路を作ろうとする | 初期UIには作成機能を提供しない |

技術性能の合格基準は代表データ量・最低PC・対象ブラウザを決めて設定する。未測定の件数やフレームレートを達成値として報告しない。
