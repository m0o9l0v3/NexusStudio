# Nexus Studio v1.0 Spots管理詳細案

- 作成日：2026-09-13。状態：決定案。新しい細部は提案であり、実装済み・一括承認済みとは扱わない。
- 保存先：利用者指定の「Nexus Studio決定事項収納フォルダ」。
- 前提：[公開方針](06_NexusStudio_v1.0_公開方針・機能境界_2026-09-12_v01.md)。イベントから会場をcanonical IDで参照し、Spot変更は地図公開へ含める案。
- 参照：Obsidian Vault/Nexus内の「データ方針」「canonical ID」「経路案内とオフライン」を2026-09-13に確認。数値データ・現地状況・API実装は未検証。

## 1. 初期範囲の案

既存Spotの一覧・検索・属性編集・座標調整を中心とし、新規Spotは下書き登録まで可能にする。公開は正式なID・出典・必要な位置と経路接続の条件を満たすものに限る。Spotの作成は、建物・道路の新規作成を含めない。

Spot一覧とMap Editorは同じデータを扱う別の入口とする。コピーされた独立データは作らない。片方で保存した変更は他方でも同じ下書き版として確認できる。

## 2. 項目と変更規則

| 項目 | 初期案 |
|---|---|
| canonical ID | 正式台帳のIDを入力・対応付け。保存後は通常の編集で変更不可。名称から自動生成しない |
| 名称 | 公開時必須。変更してもIDを維持 |
| 別名 | 任意の複数テキスト。検索用。正式名称を上書きしない |
| 種別 | 正式な種別候補から選択。候補と必須条件は既存契約の確認後に確定 |
| 建物・階 | 屋内Spotでは正式な建物・階IDを選択。屋外は適用なしを許容し、階を推定しない |
| 位置 | 座標系・座標・出典・確認状態を区別。表示用の位置と経路の到着点を混同しない |
| 説明 | 来場者向けの任意の短い説明。イベントの説明とは別 |
| 出典 | 資料名、記録の参照先、測定日・測定者等を必要な範囲で保持 |
| 確認状態 | 未確認／確認済みを根拠とともに保持。地図クリックだけで確認済みにしない |
| 利用状態 | 利用可能／新規会場選択を停止／公開取り下げを区別する案 |
| 表示設定 | ピン表示など。経路利用可否・イベント会場可否とは独立して扱う |
| 関連情報 | 下書き・公開中のイベント、建物、入口・経路との関係を読み取り表示 |

`Spot.Code == SpotDto.Id == canonical ID`を維持し、大文字・小文字を保持する。GUID・表示名への置き換え、未知IDを別地点へ代替する処理は行わない。検索文字列の便宜的な照合と、保存するIDの完全一致を区別する。

ID訂正・統合・廃止時の置換は通常フォームから除外する案。必要な場合は参照移行の個別手順を作る。正式IDが未決定なら内部の下書き識別子で保持できても、canonical IDとして公開しない。

| SP-24 | 編集競合の保護 | 古い下書きで他の保存を上書きしない |

## 4. UIと位置編集

左に一覧、中央に地図、右にInspectorを基本案とする。通常は選択モード。「位置を変更」を開始したときだけピンを移動できる。ドラッグだけでなく座標入力と取り消しを用意する。

- 屋外の緯度・経度と、屋内の平面座標を同じ欄で曖昧に扱わない。
- 屋内の階を変えただけで座標や経路を自動的に作り直さない。
- 座標変換が必要で正式な対応情報がない場合は、その編集の確定・公開条件を未達として示す。
- 近くの道路や建物へ自動吸着して、正式位置や経路到着点として確定しない。
- 出典が競合する場合は両方の値と根拠を保持して確認対象にし、平均や多数決で決めない。
- 移動してもイベントのSpot参照IDは同じ。公開後は同じ地点の位置訂正として扱うため、変更前後と関係するイベントを確認する。

## 5. 利用状態の意味

| 操作 | 新規イベント | 既存の公開イベント | 経路・表示 |
|---|---|---|---|
| ピンを非表示 | 会場利用条件が満たされれば選択可能 | 会場参照を保持 | ピンだけの設定。経路可否を変更しない |
| 新規会場選択を停止 | 新たな割り当てを禁止 | 既存参照を継続。時刻訂正等を妨げない | Spotの表示・経路は維持 |
| 公開取り下げ | 選択不可 | 参照中ならそのままの地図公開を阻止 | 地図・検索・経路の整合性を別途検証 |

未公開イベントの下書きに以前から指定してあるだけでは、公開済み参照の継続扱いにしない。初回公開時に新規選択条件を検証する。名称変更や選択停止で別会場へ自動置換しない。

## 6. 公開条件と依存

Spotの編集は地図をひとまとまりに公開する既決定の方針へ含める案。Spot名だけを個別に出す専用公開は初期案に含めない。地図内の別の編集が未完了ならSpot訂正も待つ、という制約を差分画面で明示する。イベント日時の独立公開は維持する。

| ID | 検証 | 判定案 |
|---|---|---|
| SV-01 | 正式ID不足・重複・不正な参照 | 公開阻止 |
| SV-02 | 名称など必須属性不足 | 公開阻止 |
| SV-03 | 存在しない建物・階、座標系や数値の不正 | 公開阻止 |
| SV-04 | 必要な正式位置・出典の確認が未完了 | 公開阻止または対象種別ごとの扱いを契約で決定。未確認を自動合格にしない |
| SV-05 | 必須の経路到着点・接続が欠ける／不整合 | 経路案内対象としての公開を阻止。案内対象条件はデータ契約で定義 |
| SV-06 | 取り下げるSpotを公開中イベント・経路が参照 | 公開阻止して参照元を表示 |
| SV-07 | 位置・所属変更で既存の入口／経路接続の確認が必要 | 依存検証完了まで当該変更を含む地図公開を阻止 |
| SV-08 | 公開確認後に参照元・Spot版が変更 | 再検証・再確認 |

位置と経路の関係が変わる変更は、正式な経路データを準備・検証して同じ地図版に含める。Studio内のNode・Edge編集を初期対象外とする場合でも、この公開条件は省略しない。別の整備手段による検証済みデータの取り込みを依存作業として扱う。

## 7. 受け入れ条件案

| ID | 状況 | 必要な結果 |
|---|---|---|
| SA-01 | 同名の部屋を検索 | 建物・階・IDで区別できる |
| SA-02 | 名前を変更 | ID・イベント参照を維持する |
| SA-03 | 未知IDで会場を参照 | 別Spotに代替せず検証で止める |
| SA-04 | 地図上でピンを移動 | 取消でき、出典や経路接続が自動承認されない |
| SA-05 | 座標系・階が不明 | 正式な位置へ推測変換しない |
| SA-06 | 新規会場選択を停止 | 新規割り当てを防ぎ、既存イベントの訂正を許容 |
| SA-07 | 公開中イベントの会場を取り下げ | 参照が残る地図公開を阻止 |
| SA-08 | イベントに無関係な地図下書きがある | 公開済み会場を使うイベント訂正は公開可能 |
| SA-09 | 経路接続の確認が必要な位置変更 | 位置だけで完成扱いにせず依存検証を示す |
| SA-10 | Spotを一覧とMap Editorで開く | 同じ下書き・公開版を確認できる |

## 8. 未確定のまま残す実データ条件

Spot種別・階ID・座標契約・案内必須の対象・正式ID発行手順・到着点の対応・出典承認の運用を確認する必要がある。資料の存在や既存コードだけで実測・経路接続完了と判断しない。原本・既存APIを本書作成では変更していない。
