# Nexus Studio v1.0 共通UI・運用基盤詳細案

- 作成日：2026-09-13。状態：決定案。
- 対象：Login、Overview、共通の編集体験、操作履歴、Preview、画像の基本操作、運用に必要な状態表示。
- 確定境界：PCブラウザ専用。登録済み管理者が全操作を行う。別人の公開承認は必須にしない。既存Adminの情報設計を再設計する。
- 関連：[イベント案](07_NexusStudio_v1.0_イベント管理詳細案_2026-09-13_v03.md)、[公開共通案](11_NexusStudio_v1.0_Validation・Releases詳細案_2026-09-13_v01.md)。

## 1. 画面構成案

| メニュー | 主目的 | 主な画面 |
|---|---|---|
| Overview | 公開状況と必要な作業を把握 | 公開版、対象開催、未公開変更、検証、最近の操作 |
| Events | 企画と開催枠・会場を編集 | 一覧、詳細、カテゴリ管理、Preview |
| Spots | 会場・施設を管理 | 一覧＋地図＋Inspector |
| Open Campus | 開催回・開催日・時間を管理 | 開催回一覧、日別編集、影響確認 |
| Map Data | 地図を表示・編集 | Layers、2D／3D、Inspector |
| Validation | 問題を確認して直す | 全下書き診断、公開候補の結果、修正導線 |
| Releases | 公開・取り下げ・復旧を追う | 公開確認、履歴一覧、版の詳細 |
| Logs | 操作履歴を確認 | 編集・公開等の記録と絞り込み |

カテゴリはEvents内へ配置し、独立Settingsを初期必須にしない。ログイン後はOverviewへ進む案。Welcomeやコンセプト画面は通常作業の前に挟まない。

画面切替のSidebar、主作業領域、必要なときのInspectorを基本にする。表・フォーム・地図を主役にし、カードやグラフを増やすことを目的にしない。正式なメニュー表記・画面幅・配色・余白はデザイン段階で決める。

## 2. 認証と管理者運用

- 利用できるのは登録済み管理者。公開サインアップは初期対象外案。
- 全管理者に編集・検証・公開・復旧の権限を持たせる。画面だけでなく管理APIでも認証を要求する。
- 共有アカウントを前提にせず、個人を識別できる管理者IDで履歴を残す案。
- 初期管理者の登録・無効化・アカウント復旧は利用する認証基盤の管理手段で行う案。Studio独自のUsers／Permissions画面は初期必須にしない。
- 認証方式・既存アカウントとの接続・多要素認証・セッション期限は既存基盤を確認して決める。実装前に最低限の登録／復旧手順を用意する。
- 期限切れは公開成功と表示せず、再認証後に保存版・対象版を確認する。再認証だけで保留中の公開を自動実行しない。

## 4. Overviewの表示ルール

公開版・開催日・検証結果・未公開変更を表示する。来場者数・人気ランキング・リアルタイム混雑を中心にしたAnalyticsは初期対象外。複数開催回が公開されている場合は対象選択を表示する案とし、「今日」が存在する場合も日付を明示する。

取得に失敗した値を0件・問題なしと表示しない。以前取得した値を残す場合は取得時刻・保存情報であることを示す。診断結果のエラー数だけで本番公開が壊れていると断定せず、「下書きの問題」「公開候補の問題」を区別する。

## 5. Previewの初期範囲

イベント詳細とSpot詳細の近似表示を対象とする案。イベントには複数日・枠・会場、終日と具体的な時間、随時参加、中止案内、画像なしを含める。

CSS等による汎用スマートフォン枠に、固定した論理画面サイズで表示する。特定機種の外観再現やSwiftUI実行は必須にしない。画面サイズ・ライト／ダークの初期対象はデザイン時に決める。地図の実経路案内・位置情報・お気に入りの完全再現は初期Previewの対象外案。

公開差分の確認では、公開に使う参照版の名称・場所・開催時間を使用する。未保存のPreviewと公開対象の違いを明示する。近似Previewの完成と、iOS実機での最終確認を区別する。

## 6. LogsとReleasesの役割

Logsは誰が・いつ・何をしたかの運用履歴、Releasesは何を公開したかと復旧候補を扱う。行き来できるようにし、同じ公開を別の結果として二重計上しない。

記録には安定した操作ID・操作者ID・対象ID・日時・操作・結果・関連する版を持たせる案。パスワードや認証トークン等の秘密値を保存・表示しない。システムの詳細な内部ログや任意のログダウンロードは初期対象外案。保持期間・閲覧範囲・障害調査の方法は運用設計に残す。

## 7. 画像の境界

画像はイベントに付随する1枚を基本案にする。公開中・履歴・復旧候補が参照する画像を、差し替え直後に消さない。素材の詳細管理画面、フォルダ整理、画像加工、動画対応は初期対象外案。

対応形式・容量・寸法・代替説明の入力方式はiOSと配信の契約で定義する。アップロード完了前に公開成功と表示しない。画像を任意として使わない選択を可能にする。

## 8. 受け入れ条件案

| ID | 状況 | 必要な結果 |
|---|---|---|
| UA-01 | 未認証で管理APIにアクセス | 管理データの変更を許可しない |
| UA-02 | 登録済み管理者が公開 | 別人の承認なしで完結できる |
| UA-03 | 認証期限切れの状態で公開 | 成功と誤表示せず、再認証後に確認し直す |
| UA-04 | 保存に失敗して画面を離れる | 未保存内容を失わず、戻ることができる |
| UA-05 | 一覧取得失敗・正式0件・検索0件 | それぞれを区別し適切な操作を表示 |
| UA-06 | 全下書きの検証に問題あり | 公開中のデータが壊れたと誤表示しない |
| UA-07 | 複数会場のPreview | 全会場と選択枠を確認できる |
| UA-08 | 終日・随時参加のPreview | 具体的な時間と参加案内を区別 |
| UA-09 | 画像差し替え失敗 | 公開画像を維持し再試行・解除できる |
| UA-10 | Logsから公開を確認 | 対応するReleaseと実行者・結果へ到達できる |
| UA-11 | キーボードで会場順序を変更 | ドラッグなしで完了できる |
| UA-12 | 過去の開催情報を取得 | 「今日開催」と誤表示しない |

対象ブラウザと最低画面幅、認証基盤、処理時間、履歴と素材の保持期間は実装前に決める。自動保存・予約公開・通知送信・多言語・独立した管理者権限編集は初期必須にしない案。
