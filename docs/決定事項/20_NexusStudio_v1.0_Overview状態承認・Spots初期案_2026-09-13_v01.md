## 3. 一覧・検索

- 名称、別名、canonical IDで検索する。
- 同名地点は、建物・階・canonical IDを並べて区別する。
- 選択中の行と地図・Inspectorを同じ青の選択状態で連動させる。
- サンプルとして`mb_f2_cr_2a`と`mb_f2_cr_2b`を大文字小文字を保持して使用した。
- `sample_other_2a`は同名地点の区別を確認する架空IDであり、正式台帳へ登録する値ではない。
- 表示名や近傍位置から別Spotへ自動置換しない。

## 4. 地図の境界

- 中央地図は一覧・選択・Inspector配置を確認する抽象表現。
- 建物矩形、Spotピン、ピン移動前後の位置は正式Geometry・正式座標ではない。
- 参考背景なしでも正規データを編集できる配置案。
- 表示用ピン位置と経路の到着点は別に検証する。
- 近くの建物や道路へ自動吸着して正式位置・接続済みとしない。

## 5. Inspector

- canonical IDは通常編集不可として表示。
- 名称、建物、階、種別、位置、出典、経路関係、関連イベントを同じInspectorで確認する。
- 種別、座標、出典、到着点・入口・Graph接続は「未確認」と表示し、架空値や0で補完しない。
- `floor-local（m）`の座標系を表示するが、今回のサンプルではX・Yの数値を表示しない。
- ピン移動だけで、出典や経路接続の確認状態を変更しない。
- Spot変更は地図全体の公開確認に含める案であることを表示する。

## 6. 位置変更フロー

`42:2 通常選択`
→「位置を変更」
→ `44:2 位置変更モード`

- 「編集を確定」→`44:135 変更確定・未保存`。
- 「取消」→`42:2 通常選択`。
- `44:135`の「位置を変更」→`44:2`へ再入場。
- `44:135`の「下書き保存」→`45:2 保存済み下書き`。

編集確定、取消、下書き保存、地図全体の公開を別操作として扱う。Figmaのピン移動は状態遷移の表現であり、実座標編集エンジンやドラッグ精度の検証ではない。

## 8. 次の確認事項

Spotsで確認してもらう主な点は次の3点。

1. 320px一覧・560px地図・344px Inspectorの比率。
2. 位置・出典・経路を未確認のまま明示し、ピン移動と検証済みを分離する強さ。
3. 編集確定・取消・下書き保存・地図公開を分ける操作順。

この範囲の承認後、Spotsの読み込み中・正式0件・検索0件・取得失敗・競合・位置未確認の代表状態を追加し、その後Open Campusへ進む。
