# Nexus Studio Spot 種別の必須化の判断記録

- 作成日：2026-11-02
- 版：v01
- 状態：**利用者が決定**（2026-11-02、承認者 m0o9l0v3）
- 関連：Issue m0o9l0v3/NexusStudio#11、nexus-mobile E2-5 §5.2・O-2a・O-2c、m0o9l0v3/NexusMobile#84、[29 v01](29_NexusStudio_M1地点表示の判断記録_2026-10-24_v01.md)（M1-D1）

## 1. 背景

E2-5 O-2c（C4）は、種別のない Spot の公開を、NexusMobile #84 で種別の候補が承認されるまでは警告にとどめ、承認後は Studio の公開前検証で止めると定めた。切り替えは Studio の設定または版で行い、本番で最初に公開する前に既存の Spot に種別を付ける。

## 2. 決定事項

| # | 論点 | 決定 | 補足 |
|---|---|---|---|
| K1 | 種別の候補 | **`classroom`（教室）／`facility`（施設）／`service`（サービス）の3つで承認**（2026-11-02、m0o9l0v3）。トイレを独立させる `restroom` は**採用しない**（トイレは `facility`） | 利用者決定。bundle の Schema・iOS の `SpotKind` は変わらない。DB の制約も変えない |
| K2 | 種別のない Spot | **公開阻止**（`spot_kind_missing` を Blocking に）。下書きでは引き続き未設定のまま保存できる | 契約（bundle の `kind`）は null 可のまま |
| K3 | 切り替えの方法 | **コードの版で切り替える**（設定の切り替えは設けない） | レビュー済みのコードで決まり、環境ごとに食い違わない |
| K4 | 取り込みで公開する Spot | `reference import` で `isPublished: true` の Spot に種別が無ければ、**取り込み全体を拒否**する（何も書かない） | 取り込みの公開は公開前検証を通らないため、同じ規則を取り込みの検査に置く |

## 3. 影響

- 復旧：種別の無い過去の版へ戻す復旧も、公開前検証で止まる（意図どおり）。
- 改名（32）：旧 Spot の種別を写すため影響しない。
- 設計用サンプル `docs/samples/reference-sample.json` の Spot に、E2-5 §5.2 の割り当ての指針に従って種別を付けた（正式データではない）。
- 本番で最初に公開する前に、実データの Spot に種別を付ける。値は運用側が決める（開発チームは値を決めない）。建物14棟・部屋74件の割り当ては [34 v01](34_NexusStudio_実データSpotの種別割り当て_2026-11-02_v01.md) で決めた。

## 4. 後続

- nexus-mobile E2-5 の O-2a・O-2c に、承認と `restroom` の不採用を記録する。
