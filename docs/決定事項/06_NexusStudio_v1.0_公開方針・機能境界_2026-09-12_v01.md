# Nexus Studio v1.0 公開方針・機能境界

- 決定日：2026-09-12（日本時間）
- 状態：本会話で利用者が承認した方針。実装完了を意味しない。
- 対象：Nexus Studio（PCブラウザ向け制作・管理環境）
- 承認根拠：公開方式の提案に対する利用者の「その方針で決定します。」
- 参照資料：利用者が提示した「Nexus Studioの製品・UI・3D Map Editor方針.md」。資料内の候補・将来構想は、本記録によって一括承認されたものではない。

## 1. 判断の背景

整合性を管理しやすくしつつ、急ぎのイベント訂正を、無関係な編集途中のデータによって止めない。個人で運営するプロジェクトとして、誤情報を公開しにくいことと、問題発生時に迅速に訂正・取り下げ・復旧できることを重視する。

新規Spotを使用するイベントは現状ほとんどない、という利用者の運用見込みを前提とする。ただし、未公開Spotへの参照を検出する仕組みは必要とする。

## 2. 先に確定した範囲・権限

- v1.0に建物・道路の新規作成は含めない。
- 既存建物の形状・高さ・属性編集、Spot配置などの詳細範囲は引き続き整理する。既存道路の編集範囲も未確定。
- 登録済み管理者は、Studioの編集・検証・プレビュー・公開までの全権限を持ち、1人で完結できる。
- 別の管理者による承認は必須にしない。

## 3. 公開の基本原則

公開済みの内容を土台に、管理者が確認して選んだ変更だけを反映する。

- 下書き保存だけでは、本番の公開内容を変更しない。
- 公開対象に含めなかった下書きは残し、その対象の公開済み内容を維持する。
- 急ぎの公開も、通常の公開と同じ検証を通す。検証を省略する緊急公開は設けない。

## 4. 公開単位と操作

| 対象・操作 | 決定内容 |
|---|---|
| イベント | 1件単位で公開・訂正・取り下げを行える |
| イベント内の変更 | そのイベントの変更をすべて公開対象とする。項目単位の部分公開はv1.0に含めない |
| 地図 | 地図データはひとまとまりで公開する。建物・入口・経路などの任意の組み合わせによる部分公開はv1.0に含めない |
| 変更をまとめて公開 | 変更一覧で公開対象を確認して実行する。すべての下書きを無条件に公開する操作にはしない |
| このイベントを公開 | イベント編集画面から、そのイベントの変更を確認して実行する |

地図をひとまとまりにする具体的なデータ境界、開催情報の公開単位、コンテンツと地図を同時公開する場合の詳細は、後続の仕様整理で確定する。

## 5. 検証と公開の整合性

1. 選んだ変更と、それ以外の公開済みデータを組み合わせ、公開後の状態を検証する。
2. 無関係な下書きのエラーは、選んだ対象の公開を妨げない。
3. 未公開Spotを参照するなど、関連する変更が必要な場合は、理由と必要な対応を管理者に示す。関連する下書きを勝手に公開しない。
4. 公開確認画面には、変更内容と関連データの検証結果を表示する。
5. 確認した版を公開対象とする。確認後に対象や整合性に関係するデータが変更された場合は、再検証・再確認を行う。
6. 選んだ変更はまとめて反映し、一部だけ公開された状態を作らない。公開処理が失敗した場合は、直前の公開版を維持する。

## 6. 操作履歴と復旧

- 誤情報を迅速に訂正・取り下げできることをv1.0要件に含める。
- 誰が・いつ・何を公開したかと、公開内容を追跡できるようにする。
- 問題のある公開から復旧できることをv1.0要件に含める。
- 復旧の単位、操作画面、過去版に戻す際の関連データの検証、下書きの扱いは未確定。無条件に全データを過去へ戻す仕様を決定したものではない。

## 7. 受け入れ条件として具体化する例

| 状況 | 必要な結果 |
|---|---|
| イベントAの時刻訂正が完了し、イベントBと建物Cは編集中 | Aだけ公開でき、BとCの下書き・公開済み内容は維持される |
| 建物Cの下書きに形状エラーがある | Cを含む地図公開を止めるが、無関係なAの公開は止めない |
| イベントが未公開Spotを参照している | そのままの公開を止め、開催場所の公開が必要であると示す |
| 公開確認後に対象データが編集された | 未確認の変更を混ぜず、再確認を求める |
| 公開処理に失敗した | 一部だけ反映せず、直前の公開版を維持する |

## 8. 次に具体化する項目

- イベントの状態（下書き・公開中・未公開変更あり・取り下げ等）と操作の対応。
- イベントの取り下げと、開催中止の案内表示の違い。
- 地図の公開範囲と、既存道路・Spotの編集機能の境界。
- 開催情報の公開単位と、イベントとの依存関係。
- 公開を止めるエラーと、確認後に公開できる警告の境界。
- 公開・復旧の技術方式と履歴の保持範囲。
- Studioでの公開完了から、アプリが更新を取得・表示するまでの反映条件。オフライン端末への即時反映は本方針で保証しない。

本記録は製品方針の確定記録であり、コード実装、外部Issue発行、API変更、Figma変更、実データの公開は行っていない。
